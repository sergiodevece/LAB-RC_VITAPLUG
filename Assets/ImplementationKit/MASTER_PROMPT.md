# LAB-RC — Manza’s Rooms & Chambers
## A Tribute to Steve Albini · VITALAB / VITAPLUG · Master prompt 1.0

**Destino:** Codex, con subagentes y Superpowers si están instalados y autorizados. **Idioma:** documentación y comunicación en español; etiquetas del producto en inglés. Trabaja en el repositorio local que el propietario indique. No publiques, hagas push, descargues dependencias no autorizadas ni sobrescribas otros proyectos. Si faltan herramientas o permisos, informa y continúa lo que sea posible. No simules resultados. No sustituyas la revisión humana por tests.

## 1. Misión y fuentes de verdad
Implementa LAB-RC 0.1.0, plugin C++/JUCE de mezcla de microfonía ambiental. Es un homenaje independiente inspirado en Electrical Audio, no una captura real ni producto oficial. Las tres salas son Kentucky (Studio A), Center Field (Studio A), Live Room (Studio B). El usuario ha aprobado subjetivamente las nueve IR wet v0.5 tras escucharlas en Logic; v0.6 está validada numéricamente, no en DAW. No modificar estos WAV ni regenerar las IR. El FDN y el solver geométrico se ejecutaron offline; el plugin reproduce su resultado por convolución. No introducir decay, tamaño, modulación, compresión, EQ, separación de instrumentos, nuevos modelos ni red. No oversampling por defecto: procesamiento lineal.

Los recursos de `assets/rooms` son los únicos fondos aprobados: conservar batería BOOST THIS, sin persona, sin recorte destructivo ni geometría alterada. `assets/design/approved_vintage.png` es la referencia estética aprobada, no fondo final completo: contiene una batería distinta y medidores/botones en estados ilustrativos. No usar esa escena ni hornear los rótulos dinámicos. `prototype_v01.html` define interacción anterior, no estilo. `assets/ir/v05` contiene referencia mono→estéreo; `assets/ir/v06` contiene matrices wet 2×2. `manifest.json` fija SHA-256, formato y orden de canales. `research/` contiene documentación y resultados originales, cuyo estado histórico de escucha queda actualizado por este prompt.

## 3. DSP obligatorio
- Layout mono→estéreo y estéreo→estéreo. Si un host requiere mono→mono para aceptar una instancia mono, documentar y proponer implementación explícita de fold-down, no anunciar compatibilidad sin probar. Entrada mono duplicada a unidad a ambas entradas de matriz; estéreo intacta. No downmix inadvertido, no falsa separación de batería.
- Convención WAV 4 canales input-major: [LL, LR, RL, RR]; yL=xL*hLL+xR*hRL; yR=xL*hLR+xR*hRR. Cada sala tiene EARS, FRONT, FLOOR, tres matrices independientes. 12 convoluciones mono por sala o equivalente matemático con M/S. JUCE Convolution estéreo ordinaria no equivale por sí sola a matriz cruzada: dividir canales explícitamente. v05 no se usa como capa adicional. No normalizar, recortar, alinear picos, compensar retardos acústicos ni introducir predelay. Conservar amplitud relativa y origen temporal. Resampling con ganancia de convolución coherente (área de impulso / respuesta de transferencia), validar frente a referencia a cada SR. No aplicar gain automático por número de parejas.
- Fs 44.1, 48, 88.2, 96, 176.4, 192 kHz; bloques variables incluidos 1, 32, 64, 127, 128, 256, 512, 1024, 2048; bloques mayores que el tamaño de preparación: chunk sin allocation. Carga y preparación de IR fuera del callback. Recursos disponibles sin internet, empaquetados con plugin. Precalentar/preparar motores antes de intercambio, nunca reconfigurar con audio activo. Reportar latencia computacional real al host; alinear dry y todas las rutas. Mantener tiempos físicos de IR. No allocations, mutex, I/O, logs, destrucción de objetos pesados, resampling o compilación en audio thread. Denormals, NaN/Inf defensivos, estado inicial silencioso. Float32, double si implementado y probado; no anunciar double si no existe.
- Room switch: petición atómica, preparación off-thread, crossfade inicial propuesto de 50 ms complementario entre salidas; mantener old/new durante transición, no corte abrupto. Política explícita: cola anterior se atenúa en crossfade, no prometer spillover íntegro. Cambios rápidos: coalescer a última selección; no free en RT, no más de dos bancos activos durante transición. Evitar click, silencio inesperado, picos, latencia variable; si no se puede sostener CPU, medir y proponer alternativa antes de cambiar diseño. Mantener faders globales entre salas (no presets por sala en v1).
- Faders wet EARS/FRONT/FLOOR: ganancia posterior a convolución. Mute prevalece sobre solo; múltiples solos simultáneos; sin solo suenan canales no muteados. Suavizar ganancia, mute, solo, mix, trims y bypass (20 ms inicial). No suspender convolución de pareja muteada/solo excluida si rompería continuidad de cola; medir. Fader mínimo -60 dB no es mute matemático. Medidores de pareja post-fader/mute/solo, IN post-trim, OUT post-mix/trim (estéreo); peak dBFS, decay visual, clip indicador a 0 dBFS. GUI lee snapshots atómicos, no acceso bloqueante. Sin limitador oculto.
- Señal propuesta: u = inputTrim*x; wet=sum(pairGain*pairGate*conv(u)); out=outputTrim*((1-mix)*dryAligned(u)+mix*wet). MIX lineal 0–100%, sin ganancia extra ni duplicación dry en wet. 0% dry con trims; 100% wet. Bypass plugin/host: dry original a unidad compensado por latencia; transición suave, preserva parámetros. Mantener motores calientes si CPU lo permite; distinguir bypass host si su API no permite fades. Reportar tail conservador al menos 4.5 s + latencia, documentar. Nada de ajustes ocultos para igualar salas.

## 4. Parámetros iniciales propuestos (no alterar sin justificar)
IDs persistentes APVTS, valores en unidades reales, versionHint estable. room choice Kentucky / Center Field / Live Room (0). inputDb [-18,+18] step .1 default 0; outputDb igual; mixPercent [0,100] step .1 default 100. earsDb/frontDb/floorDb [-60,+6] step .1 defaults -6/-3/-9; earsMute/frontMute/floorMute, earsSolo/frontSolo/floorSolo bool default false; bypass bool default false. UI-only micsVisible=true y editorWidth/editorHeight guardados por instancia, no automatización para preferencias visuales. Automatizar parámetros DSP, gestures begin/end, UndoManager y redo para cambios de usuario, reset en una transacción deshacible; no crear acciones de undo por audio/host automation ni asumir soporte global del DAW. Estado versionado, tolerar estado antiguo/inválido, clamp y defaults; persistencia exacta al cerrar/reabrir, reiniciar host y duplicar instancia. No conservar datos de otra sesión en disco global.

## 5. UI: referencia visual vinculante
Layout como `approved_vintage.png`: 1586×992 de referencia, ratio ~1.60, tamaño inicial propuesto 1180×738, resize proporcional 800×500 a 1586×992, HiDPI, estado persistente. Chasis verde oscuro envejecido, pátina fina, metal con desgaste real, tornillos viejos, biseles, tipografía crema, knobs metálicos cepillados con indicador oscuro, faders setenteros tipo consola británica/Neve (sin logos ni copia literal), recorrido real, ranura profunda, cap metálico con estrías. Mantener identidad VITALAB, VITAPLUG, LAB-RC y título exacto. No volver a estilo flat; no adoptar look genérico JUCE ni usar emoji. Faders y knobs independientes del fondo: texturas estáticas y componentes dinámicos, PNG/SVG según convenga; no usar el screenshot completo como fondo con controles congelados. No distribuir fuentes sin licencia. Diseñar estado normal, hover, pressed, activo, desactivado. LEDs reales: SOLO solo iluminado cuando está activo, MUTE cuando muteado, meters en silencio apagados; la maqueta no determina estados de DSP. No duplicar controles con sliders pequeños si el knob ya es interactivo, salvo necesidad de accesibilidad. Valores numéricos editables, drag fino, rueda con control de foco, doble clic a default, teclas, tooltip, focus visible. Evitar jitter de labels.
- Header título/tributo; fila tres selectores de sala (excluyentes); escena central con fondos originales sin estirarlos (contain), laterales INPUT/OUTPUT/MIX/BYPASS; parte inferior tres módulos EARS/FRONT/FLOOR, faders, M/S (mute/solo, no Mid/Side), LEDs y medidores estéreo; RESET abajo. MICS ON/OFF solo cambia overlays. Posiciones de micrófonos son aproximaciones gráficas, no controles de DSP, sin arrastre; 6 marcadores L/R, tres colores discretos; asociar a cada pareja. No dibujar micros o recrear fondos sin aprobación. Si se usan siluetas de micrófonos más realistas, mantener geometría y hacerlas capa separada. El usuario revisará captura antes de cerrar fase UI.
- Fader: escala dB no lineal tipo consola, p.ej. anclas t 0/0.15/0.36/0.65/0.86/1 => -60/-43/-27/-10/0/+6; interpolación monótona e inversa exacta. Marcas y valores reales coinciden. Knob y valor numérico sincronizados; todos los controles con hit area adecuada. UI refresh ~30 Hz, no audio thread repaint. No clipear textos/controles a ningún tamaño. Accesibilidad por teclado y nombres.

## 6. QA y gates
- Gate 0: verificar cada SHA-256, dimensiones PNG, WAV float32, sample rate, orden, frame count y duración. `python verify_assets.py` en raíz del paquete (requiere numpy/scipy). No alterar recursos de origen. Registrar licencia y procedencia.
- Gate 1 (DSP): test de impulso L-only/R-only para las nueve matrices; compara canales cruzados contra referencia offline. Mono idéntico L/R reproduce v05 a 96k (error de assets <4e-9; tolerancia propuesta del motor FFT abs <=2e-5 con señal de referencia a unidad, excluyendo solo latencia computacional). Pruebas de convolución random/impulso a todos SR, resampling contra oracle independiente, bloques variables y duración tail; documentar tolerancia numérica y espectral por SR. Dry/wet endpoints, trims, mute/solo truth table, fade sin discontinuidad artificial, bypass, silencio, estabilidad, finite, clipping reportado no oculto. Verificar mono estéreo y suma mono. Control de estado y automatización a límites, cambios rápidos de sala, cambio de SR/bloque, múltiples instancias, stress sostenido con audio real y reproducción/detención. Medir CPU (media/pico p95/p99, entorno, buffer, Fs, instancias) y memoria; no prometer presupuesto no medido. Sanitizers debug si disponibles, release benchmark. Reportar cada test y fallo.
- Gate 2 UI: screenshots de cada sala, tamaños min/default/max y HiDPI; comprobar layout y recursos idénticos, faders/knobs y edición numérica, selector, mute/solo, meter, bypass, reset y undo/redo, resize y persistencia. Revisar con propietario. No declarar diseño final implementado por tener solo screenshot.
- Gate 3: AU universal macOS arm64/x86_64 (deployment target propuesto 11.0/10.15 respectivamente si JUCE/SDK/arquitectura lo soporta; reportar incompatibilidad en vez de fingir). VST3 Windows x64 (build real en Windows o CI autorizado, no anunciar prueba Windows desde macOS). Elegir códigos fabricante/plugin de cuatro caracteres únicos tras inspeccionar productos VITALAB; no cambiar una vez publicados. Bundle ID estable, version 0.1.0. `auval -v aufx <code> <manufacturer>` con códigos reales, comprobar lipo, codesign local según entorno, no desactivar Gatekeeper global. Scripts de instalación/desinstalación limitados al propio bundle, cotas de rutas quoted; no sudo por defecto. Windows: paquete .vst3 y procedimiento instalación estándar; no reclamar firma/notarización si no realizada. CTest y pluginval si instalado y autorizado. Host Logic 12.2 (usuario): mono→estéreo, estéreo, aux, automatización, undo/redo, resize, recall, bypass, tails, CPU, comparaciones de las 9 IR con Space Designer, A/B nivelado, caja, bombo, toms, platos, mono. Smoke humano imprescindible. Windows smoke posterior. Si host o plataforma inaccesibles, marcar PENDIENTE.
- Gate 4: README (build limpio reproducible, arquitectura, licencia, referencia acústica sintética, limitaciones), CHANGELOG, test report, manifest y screenshots; dist con AU zip universal verificado, VST3 Windows si construido, fuentes, scripts, hashes. No publicación automática. Informar exactamente rutas locales, comandos y resultados. Separar validación matemática, pruebas de software y escucha humana. No inventar PASS.
